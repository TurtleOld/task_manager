# Файл вложения общий для копий, удаляется по последней ссылке

AUDIT-013 показал, что новый экземпляр Повтора получает копии строк `Attachment` с тем же `path`, а удаление вложения в любом экземпляре удаляло файл у всей серии. По [CONTEXT.md](../../CONTEXT.md) вложение принадлежит экземпляру, поэтому строки остаются независимыми, а физический файл — общим: он удаляется после коммита только тогда, когда на его `path` не ссылается ни одна строка `Attachment`. Это же правило применяется к Удалению задачи и списка, которые раньше оставляли файлы на диске навсегда.

## Considered Options

- **Копировать файл при генерации экземпляра.** Отклонено: диск растёт пропорционально числу экземпляров серии, а на проде уже есть строки с общими `path` — подсчёт ссылок понадобился бы всё равно либо пришлось бы физически размножить файлы data-миграцией.
- **Вложение принадлежит серии, а не экземпляру.** Отклонено: удаление чека за апрель стирало бы чек за март; требует новой модели и противоречит глоссарию.

## Consequences

- Путь `cards/{id}/…` указывает на задачу, в которую файл загрузили, а не на задачу, которой принадлежит строка; удаление первого экземпляра серии не трогает файл, пока на него ссылаются копии.
- Генератор повтора берёт `select_for_update()` на копируемые строки `Attachment`, иначе удаление может проверить ссылки до коммита новой копии и удалить файл, на который она будет указывать. Проверяется на PostgreSQL.
- Ошибка удаления файла логируется и не отменяет удаление строки: лишний файл на диске безопаснее строки без файла.
