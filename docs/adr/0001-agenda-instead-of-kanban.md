# Агенда по срокам вместо канбан-доски

Продукт задумывался как канбан-доска (приложение Django так и называется — `kanban`), но используется семьёй для домашних задач, у которых нет стадий работы: задача либо выполнена, либо нет. Колонки не несли смысла, зато были структурной опорой модели — выполненность выражалась не свойством задачи, а её принадлежностью колонке с `is_done=True`. Мы убираем `Column` из модели целиком и заменяем доску агендой, где задачи автоматически группируются по сроку, а выполненность становится собственным свойством задачи (`completed_at`, `completed_by`). Словарь предметной области зафиксирован в [CONTEXT.md](../../CONTEXT.md).

## Considered Options

- **Агенда как второй вид рядом с доской.** Отклонено: сохраняет обе модели и удваивает поверхность поддержки ради вида, которым семья не пользуется.
- **Убрать колонки из интерфейса, оставив в БД.** Отклонено: колонка продолжала бы влиять на генерацию повторов, автоперенос из инбокса и напоминания о просрочке, оставаясь невидимой и неисправимой для пользователя.

## Consequences

- Android-клиент ломается сразу: `CardDto.column` объявлен non-nullable, есть `GET columns/` и `MoveCardRequest(to_column)`. Риск принят осознанно — мобильной версией не пользуются до её переписывания.
- Удаление таблицы необратимо, поэтому выкат разделён на две миграции: сначала добавление и заполнение полей выполненности, затем, после недели эксплуатации и бэкапа БД, удаление `Column`.
- `completed_at` и `completed_by` для уже выполненных задач восстанавливаются из `CardActivity`: `column_id` входит в `TRACKED_CARD_FIELDS`, поэтому журнал хранит автора и момент перехода в done-колонку.
- Вместе с колонками уходят инбокс (`Board.is_inbox`, `InboxSchedule`), шаблоны досок и ручной порядок задач — порядок внутри группы становится автоматическим.
