# Архив списка скрывает его задачи, не архивируя их

Архивация списка (`BoardViewSet.archive`) выставляет только `Board.archived_at` и до сих пор ни на что не влияла: `ActiveCardManager` исключал архивированные задачи и колонки, но не доски. Из-за этого задачи списка, убранного в архив, продолжали жить во всех активных поверхностях — агенда «Все списки», «Семья сегодня», просрочка и поиск, — хотя [CONTEXT.md](../../CONTEXT.md) уже фиксировал «В архиве» как «убраны с глаз». Мы объявляем архив списка правилом видимости, а не состоянием задачи: `ActiveCardManager` дополнительно требует `board__archived_at is None`, при этом сами задачи не помечаются архивированными, доступ по id остаётся (ссылки из уже отправленных уведомлений не ломаются), а разархивация списка возвращает их без обратной миграции.

## Considered Options

- **Каскадно архивировать задачи списка** (`Card.archived_at` для всех карточек). Отклонено: смешивает два разных действия — человек архивировал список, а не каждую задачу, — и делает разархивацию несимметричной, пока не заведена провенанс-метка «заархивирована списком», иначе вручную архивированные задачи вернулись бы вместе с остальными.
- **Фильтровать `board__archived_at` явно в каждом запросе** (агенда, статистика, просрочка, поиск). Отклонено: правило размножилось бы по вызывающим местам, и любой новый запрос `Card.objects` снова протекал бы — ровно та причина, по которой находка возникла.
- **Показывать задачи скрытого списка на странице «Архив».** Отклонено в рамках этого решения: «Архив» перечисляет архивированные карточки, а не содержимое архивированного списка; чтобы увидеть задачи, список разархивируют.

## Consequences

- default-менеджер `Card.objects` меняет смысл: это «задачи активного семейного пространства» (задача, колонка и список активны), а не «задачи активных колонок». `Card.with_archived` остаётся выходом за правило для «Архива» и restore, а `Card.objects.active_regardless_of_list()` — для доступа по id.
- Правило применяется и к тому, что видит задача-контейнер: повтор на архивированном списке не порождает следующий экземпляр, а личные напоминания о сроке для таких задач не доставляются — как если бы задача была в архиве.
- `BoardViewSet.archive` не трогает строки задач, поэтому разархивация и force-delete остаются прежними: первая просто возвращает видимость, второй удаляет доску вместе с задачами по каскаду FK.
- Схема не меняется — миграция не нужна.
