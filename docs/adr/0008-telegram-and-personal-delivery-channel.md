# Telegram и личный выбор единственного канала доставки

Пересматриваем ограничение [ADR-0003](0003-web-push-as-the-only-channel.md): Telegram
возвращается с доступной каждому пользователю привязкой через бота и явным выбором
«Push / Telegram / Выключено». Один пользователь получает персональную внешнюю
доставку через один выбранный канал; сбой Telegram не включает резервный Push.
Подписки устройств сохраняются, Входящие не зависят от выбора внешнего канала.

## Рассмотренные варианты

- Независимые переключатели каналов позволяют случайно включить дубли. Выбран
  единственный личный канал с отдельным подтверждением перехода после привязки.
- Только личные сообщения не покрывают потребность в семейном чате. Для Telegram
  пользователь выбирает личный или семейный чат, но личные напоминания всегда
  отправляются лично. Поэтому личная привязка обязательна при любом выборе Telegram.
- Автоматический резервный Push при отказе Telegram создаёт риск дублей и нарушает
  личный выбор. Остаются повторные попытки в выбранном канале и Входящие приложения.

## Последствия

- Один общий бот семьи настраивается сервером через .env. Общий чат подключает
  администратор; личную привязку и канал каждый пользователь меняет самостоятельно.
  chat_id определяется автоматически через проверяемую одноразовую ссылку.
- Одно событие публикуется в семейный чат один раз для всех подходящих получателей.
  Участник с выбранным Push может также увидеть это сообщение; такая видимость
  общего чата принята явно и не отменяет независимость личных настроек.
- Отключение общего чата или подтверждённая потеря доступа переводит групповых
  получателей в личный Telegram; временная сетевая ошибка не меняет адресата.
- Смена канала отменяет ожидающие отправки сообщения старого канала без повторной
  рассылки истории. Уже начатая отправка может завершиться после переключения.
- Личная Telegram-привязка переживает выход из приложения, но не явное отключение
  или блокировку аккаунта. Это отличается от устройств Push, привязанных к сессии.
- Отключение личной привязки при выбранном Telegram автоматически включает Push
  вместо Telegram, в том числе при выбранном семейном чате. Используются сохранённые
  активные устройства; если их нет, требуется подключить устройство. При уже
  выбранных Push или «Выключено» удаление привязки сохраняет личный выбор.
  Автоматический переход при явном отключении не применяется к сбоям Telegram.
- Очередь остаётся в PostgreSQL по ADR-0002. Telegram использует существующий
  внешний прокси, выбранный администратором self-hosted установки и заданный через
  .env. Реализация прокси не ограничивается; запуск VPN проектом не требуется.
- Отказ от параллельных каналов не гарантирует exactly-once при неопределённом
  результате сетевой отправки.

Детали: [.scratch/telegram-notifications/spec.md](../../.scratch/telegram-notifications/spec.md).
ADR-0003 сохраняет описание механики Web Push (VAPID, таблица устройств) и
пересматривается этим решением в части «единственного канала»: личный канал
доставки теперь выбирается из Push и Telegram, семейный чат покрывается ADR-0008.
